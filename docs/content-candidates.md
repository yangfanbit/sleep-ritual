> 筛选标准：情绪共鸣 / 认知提升 / 科学严谨 / 表达生动 / 实用价值。
> 额外约束（来自 PRD）：**夜间只展示一条、低刺激、不羞辱、不恐吓**，每条尽量 ≤80 字。
> 标签对应 App 内 9 个熬夜原因 id，用于"按原因匹配内容"（见文末建议）。

## 二、明确不入选的内容及原因

- **中医恐吓类**（"子时不睡不给治""等死吧"）：违反不羞辱、不恐吓原则，且来源不严谨。
- **"448 呼吸法 60 秒入睡"**：数字无据；若要用呼吸法，改写为无承诺版本（如条目 18）。
- **"午休超 1 小时老年痴呆 +40%"、"胃癌增长 80%"**：数据存疑，见 sleep-content.md 附录。
- **劝睡随笔中夹带粗口的句子**：与夜间低刺激调性冲突，只取净化后的句子（如条目 12）。
- **一切"必须/死命令/咬牙坚持"式表达**：与产品"不羞辱式反馈"原则冲突。

## 三、内容库搭建建议

### 3.1 分类：双轴标签，而不是单一分组

**功能轴**（内容扮演什么角色）：
- `认知重构` —— 回答"睡眠为什么值"（条目 1-9）
- `情绪共鸣` —— 回答"我懂你为什么不想睡"（条目 10-14）
- `行为提示` —— 回答"现在做哪一件小事"（条目 15-20）

**干预轴**（对应哪个熬夜原因）：直接复用 App 已有的 9 个 reason id 作为标签（`not_over`、`keep_scrolling`、`no_me_time`、`work_unfinished`、`bad_mood`、`fear_tomorrow`、`finish_content`、`not_sleepy`、`other`），另设 `通用` 兜底。

**理由**：这个产品的内容不是"资讯"，是干预链条上的一环（为什么不睡 → 理解 → 缓冲 → 微行为）。按干预点打标签，内容才能嵌进流程；按传统主题分类（健康/科学/文学）对产品没有操作价值。

### 3.2 存放结构

沿用现有 IndexedDB `content` store，扩展字段即可，不动架构：

```json
{
  "id": 1,
  "type": "quote | excerpt | tip | self",
  "text": "……（≤80 字）",
  "source": "sleep-content.md §1.1",
  "tags": ["keep_scrolling"],
  "axis": "认知重构",
  "enabled": true,
  "lastShownAt": "2026-08-16",
  "createdAt": "ISO 8601"
}
```

- `tags` / `axis`：服务于匹配与管理。
- `lastShownAt`：用于防重复轮换。
- `enabled`：软删除——比起删掉，先禁用，素材可回溯。
- 种子数据仍放 `js/content.js`（离线首启可用）；用户的增删改在 IndexedDB，JSON 导出已覆盖备份。

### 3.3 展示形式：每晚一条，按原因匹配

**明确不做**：卡片流、专题合集、内容浏览页——全部违反"不做内容消费流、停留越短越好"的硬约束。内容在 App 内唯一的展示位就是 Night Mode 顶部那一条。

**建议的选取逻辑**（优先级从高到低）：
1. 用户选了原因 → 从匹配该原因标签、且近 14 天未展示的条目中随机取一条；
2. 未选原因 → 从 `通用` 池按同样规则随机；
3. 池子耗尽（都展示过）→ 重置 `lastShownAt` 重新开始。

**轮换节奏**：库容 30-50 条为宜，每晚一条，一个月不重样。宁缺毋滥——同一句话第三晚再出现时仍有力量，烂内容第一晚就稀释信任。

**早晨内容位**（预留）：Morning Mode 目前是固定文案。如果以后加内容，从 `行为提示` 轴里挑"晨间动作"类（如条目 20），与夜间内容用 `axis` + 标签区分即可，不用新建表。

### 3.4 质量控制流程

1. 新条目先过"四问"：有没有羞辱？有没有恐吓？夜间看着刺不刺激？80 字内能不能说完？——任一不过，改或弃。
2. 涉及数字/研究的条目，必须能在 sleep-content.md 里找到出处段落；附录"存疑清单"里的表述一律不入库。
3. 每月复盘一次：哪些条目出现时当晚拖延时间明显短，保留；无感的，禁用。数据就在 `nightSessions.contentId` 里，第一阶段的数据模型已经为此留好了位置（`contentId` 字段已在记录）。
